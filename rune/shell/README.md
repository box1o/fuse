# Rune shell platform

Rune is a standalone Bash utility library and modular command runtime. It does
not depend on the Go application under `cmd/`.

## Architecture

```text
shell/lib/        Generic reusable Bash utilities
shell/runtime/    Command registry, modules, help, lifecycle, and scaffolding
runtime/modules/  Application-specific modules
rune              Project-root symlink to shell/runtime/cli.sh
```

The generic library can be used independently. The runtime discovers immediate
module directories containing `module.sh`, automatically loads their shell
files, and exposes only explicitly registered commands.

## Requirements

Required: Bash 4.3+, Linux, GNU coreutils, `realpath`, `stat`, and `sha256sum`.

Optional features use `curl`, `flock`, `tar`, `unzip`, and Mike Farah `yq` v4.
Development uses Bats, ShellCheck, and shfmt.

On Arch Linux:

```bash
sudo pacman -S bats shellcheck shfmt go-yq curl
```

## Make `rune` available

Create a development link in `${HOME}/.local/bin`:

```bash
make link
```

Ensure that directory is on `PATH`, then run:

```bash
rune --help
```

Select another existing `PATH` directory when needed:

```bash
make link RUNE_LINK_DIR=/your/path/bin
```

The link points into this checkout and must be recreated if the project moves.
Remove it with `make unlink`.

## Writing a module

A module author does not resolve directories or source files. Rune recursively
loads every `*.sh` file except `module.sh` and files below `tests/`, then sources
`module.sh` last. Files are loaded in lexical order.

```text
runtime/modules/example/
├── module.sh
├── vars.sh
├── run.sh
└── tests/
    └── run.bats
```

Keep a small command in one file. Use a command directory only after its
implementation becomes large enough to have clear, independent parts.

The complete declaration can be this small:

```bash
module::register \
    --name example \
    --description "Example commands"

command::register \
    --cmd run \
    --handler example::run \
    --description "Run the example"
```

`module::register` requires only `--name`. Description, summary, version,
runtime API, root, and lifecycle handlers have defaults. `command::register`
requires only `--cmd` and `--handler`; it knows which module is loading.

Define `_init` only when the module needs variables. Rune creates an associative
array for the module and passes its name to the function:

```bash
example::_init()
{
    local -n _example_=${1}

    local __cache__="${XDG_CACHE_HOME:-${HOME}/.cache}/rune/example"
    var::update _example_ cache "${__cache__}"
}
```

Commands read values without knowing the backing array name:

```bash
example::run()
{
    local __cache__
    __cache__=$(module::var example cache) || return
}
```

Rune detects `example::_init` and `example::_shutdown` automatically. Explicit
handler flags remain available for unusual cases. Command help is generated by
the runtime, so command files do not need their own `_usage` function.

Module functions must be namespaced, return statuses instead of exiting, avoid
global shell-option changes, and use public registry APIs. Loading must have no
network, mount, process, or user-file side effects. `_init` must be lightweight
and idempotent.

## Additional module roots

Use a colon-delimited path or a one-command override:

```bash
RUNE_MODULE_PATH=/path/one:/path/two rune module list
rune --modules-dir /path/to/modules module list
```

Modules are executable Bash code. Only load trusted roots.

## Generic library

Load only the reusable utilities with:

```bash
source /path/to/cracker/shell/lib/init.sh
```

Public functions use `namespace::function`. See
[`usage.example.md`](usage.example.md) for examples.

### Argument parsing

Use the `args` namespace instead of repeating option-parsing loops:

```bash
args::reset
args::flag --name verbose --short v
args::option --name output --short o --required
args::option --name format --default text

args::parse "$@" || return

if args::has verbose; then
    log::debug "Verbose output enabled"
fi

output=$(args::get output) || return
format=$(args::get format) || return
mapfile -t positional_values < <(args::positionals)
```

Supported input forms include `--output value`, `--output=value`, `-o value`,
boolean flags, defaults, required options, positional arguments, and `--`.
Combined short flags such as `-vq` are deliberately rejected to keep parsing
predictable.

## Security notes

- Runtime dispatch never uses `eval`.
- Module and command identifiers are strictly validated.
- Duplicate modules and commands fail.
- Failed module loads roll back partial registry entries.
- Scaffold refuses traversal and never replaces nonempty destinations.
- Modules are trusted executable code.
- `chroot` changes filesystem root; it is not a security sandbox.
- Secrets and authorization headers must never be logged.

## Naming configuration

`rune` is registered centrally as `cli|name`. `RUNE_CLI_NAME` may override the
display/cache namespace for controlled environments. It does not rename the
physical executable or development symlink.
